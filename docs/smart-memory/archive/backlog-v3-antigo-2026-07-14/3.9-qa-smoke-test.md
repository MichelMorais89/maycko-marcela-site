# Story 3.9: QA Final + Smoke Test Cross-Page V3

## Objetivo

Validar que todas as páginas V3 (stories 3.1 a 3.8) funcionam corretamente em desktop e mobile, sem regressões visuais, quebras de paleta, links mortos ou violações das regras editoriais inegociáveis.

## Acceptance Criteria

- [ ] AC1: Todas as rotas respondem sem erro 404 ou 500: `/`, `/metodo`, `/mentoria`, `/biografia`, `/conteudo`, `/blog`, `/blog/[slug]`, `/contato`
- [ ] AC2: Redirect `/sobre` → `/biografia` retorna 301 sem loop
- [ ] AC3: Nenhum bloco com escuro-em-escuro (fundo escuro + card escuro) em nenhuma página
- [ ] AC4: Ritmo de fundos respeitado em todas as páginas (claro → escuro → claro → claro+dourado)
- [ ] AC5: Vocabulário auditado — zero ocorrência de "superar / restaurar / salvar / crise" em textos visíveis
- [ ] AC6: Navegação global (SiteNav) sem link quebrado — todos os links apontam para rotas existentes
- [ ] AC7: Mobile responsivo sem overflow horizontal em nenhuma página (viewport 375px, 390px, 428px)
- [ ] AC8: Formulário de /contato funcional (preencher → submeter → ver estado success/error)
- [ ] AC9: Formulário de aplicação em /mentoria funcional — 3 steps navegáveis
- [ ] AC10: Core Web Vitals: LCP < 2.5s e CLS < 0.1 na HOME em Lighthouse (mobile)

## Escopo

**IN:**
- Smoke test de todas as 8 rotas listadas em AC1
- Auditoria visual de paleta e contraste
- Auditoria editorial de vocabulário
- Teste de formulários (contato + aplicação)
- Teste de responsividade mobile em 3 viewports
- Lighthouse na HOME

**OUT:**
- Não fazer teste de carga ou performance de backend
- Não fazer teste de integração com APIs externas (newsletter, analytics) — ainda não integradas
- Não fazer teste de acessibilidade completo (WCAG) — fora do escopo desta sprint
- Não fazer SEO técnico completo (robots, sitemap) — fora do escopo desta sprint

## Contexto Técnico

**Worktree:** `_v3-dev/` — testes rodam contra este worktree (porta separada), não contra o V2.

Esta story bloqueia o merge de `_v3-dev/` na branch principal e o deploy de produção. Deve ser iniciada somente após stories 3.1 a 3.8 concluídas.

Agente responsável: sites-qa. Usar preview deploy do worktree (Vercel) para testes. V2 deve continuar funcionando em paralelo durante o QA.

# Story 3.8: /contato Elaborado + Interativo

## Objetivo

Reformular completamente `/contato` — de página utilitária mínima para experiência elaborada e interativa. Base bege dominante, estrutura de 4 blocos, formulário com micro-interações sofisticadas e canais diretos com hover 3D leve. Conteúdo alinhado ao playbook: construção/elevação, tom convidativo.

## Estrutura de blocos V3 (sequência obrigatória)

1. **Hero curto** — eyebrow + headline convidativa. Fundo bege (sem foto dominante).
2. **Canais diretos** — Instagram + WhatsApp + email em cards elegantes clicáveis com hover 3D. Fundo bege.
3. **Formulário** — visualmente rico, floating labels, validação em tempo real, estados de loading e sucesso. Fundo bege ou cream.
4. **"Por que entrar em contato"** — 3 razões editoriais curtas. Fundo bege.
5. **CTA secundário** — link para aplicação da mentoria (não é o objetivo principal da página). Fundo bege ou cream.

## Acceptance Criteria

- [ ] AC1: Base bege dominante em toda a página. Sem bloco escuro — /contato não tem foto dominante em nenhum bloco. Bloco sem foto = bloco claro. Sem exceção.
- [ ] AC2: Hero curto com copy literal: eyebrow "Vamos conversar" + headline "O primeiro passo começa com uma conversa". Fundo bege.
- [ ] AC3: Bloco de canais diretos com cards elegantes clicáveis para Instagram (Marcela: link confirmado; Maycko: placeholder), WhatsApp (placeholder) e email (placeholder). Fundo bege.
- [ ] AC4: Cards de canal com **hover 3D leve** — mesmo padrão `InteractiveCard3D` já usado no projeto (pode reutilizar o componente se existir).
- [ ] AC5: Formulário com **floating labels** — label flutua para cima no focus/preenchido.
- [ ] AC6: Formulário com **validação em tempo real** — erro sutil (vermelho WCAG AA), sucesso sutil (verde WCAG AA). Sem validação só no submit.
- [ ] AC7: Campos com **focus states elaborados** — borda dourada expandindo + subtle glow. Nunca focus state padrão do browser.
- [ ] AC8: Botão submit com **estado de loading** (spinner elegante) e **estado de sucesso** (checkmark animado + mensagem de confirmação).
- [ ] AC9: Bloco "Por que entrar em contato" com as 3 razões literais do copy oficial. Fundo bege.
- [ ] AC10: CTA secundário para aplicação da mentoria — presente mas não dominante (não compete com o formulário como objetivo principal).
- [ ] AC11: **Reveal no scroll** de cada bloco — stagger suave entre os blocos.
- [ ] AC12: Tipografia default para fundo claro: `--text-primary` (grafite), links em vinho, ícones em dourado/vinho.
- [ ] AC13: Acessibilidade completa — `aria-live` nos erros de validação, foco visível (não removido por CSS), tab order lógico, labels associados corretamente aos inputs.
- [ ] AC14: `prefers-reduced-motion` — todas as animações (reveal, hover 3D, spinner, checkmark, focus glow) têm fallback estático.
- [ ] AC15: Backend do formulário — se existir integração no KV/V2, manter. Se não, stub com `console.log` + toast de confirmação e comentário `// TODO: integrar backend de envio`.
- [ ] AC16: Zero vocabulário proibido — "superar / salvar / restaurar / crise / reconciliar"

## Escopo

**IN:**
- `_v3-dev/app/(marketing)/contato/page.tsx` — reformulação completa com 5 blocos
- `_v3-dev/components/contato/HeroContato.tsx` — hero curto, copy oficial, bege
- `_v3-dev/components/contato/CanaisDiretos.tsx` — cards com hover 3D, links reais/placeholders
- `_v3-dev/components/contato/ContactForm.tsx` — reescrever: floating labels, validação tempo real, focus states, loading/success states
- `_v3-dev/components/contato/PorQueContatar.tsx` — 3 razões editoriais, bege
- `_v3-dev/components/contato/CtaSecundario.tsx` — link para /mentoria ou aplicação
- Reutilizar `InteractiveCard3D` se disponível no projeto para os cards de canal

**OUT:**
- Não adicionar mapa geográfico — /contato é mentoria online, mapa não faz sentido
- Não criar backend de envio de email — stub apenas se não houver backend atual
- Não adicionar bloco escuro — /contato não tem foto dominante
- Não alterar nav/footer (escopo de 3.0 e 3.1)

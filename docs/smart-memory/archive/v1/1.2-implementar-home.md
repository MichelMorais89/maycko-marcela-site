# Story 1.2: Implementar a HOME

## Objetivo

Implementar a página `/` (Home) em Next.js 15, pixel-fiel ao protótipo `home.html` + `home.jsx` do bundle KV, com todos os 9 blocos, componentes shared (nav, footer, reveal) e integração com os tokens do DS via Tailwind v4.

## Acceptance Criteria

- [ ] AC1: Rota `/` renderiza sem erros. `pnpm build` e `pnpm start` funcionam sem warnings de produção.
- [ ] AC2: Todos os 9 blocos implementados em ordem e visualmente fiéis ao protótipo (comparar com `site/docs/elevem-se-kv-site/project/screens/01-home-scroll.jpg` a `04-home-scroll.jpg` e `01-home-sec.jpg` a `05-home-sec.jpg`): `Hero`, `Prova`, `Dores`, `Conceito`, `MetodoResumo`, `Mentores`, `Depoimentos`, `Legado`, `FinalCta`.
- [ ] AC3: `SiteNav` funcional — logo, links de navegação com estado ativo `home` (underline dourado), drawer mobile abre/fecha em viewport < 1000px, CTA "Quero a mentoria" no desktop.
- [ ] AC4: `SiteFooter` funcional — logo, copy da mentoria, form de newsletter com estados idle/loading/success/error, 4 colunas de links, copyright.
- [ ] AC5: `MobileCTABar` aparece após 560px de scroll em viewports < 1000px, oculta perto do footer. Animação de slide-up.
- [ ] AC6: Componente `Reveal` via Framer Motion (fade + translateY 18px, 420ms, ease entrance). Respeita `prefers-reduced-motion` (animação desabilitada).
- [ ] AC7: Todas as fotos via `next/image`. `priority={true}` na foto do Hero. `sizes` corretos por contexto. `objectPosition` preservado de cada bloco.
- [ ] AC8: CTAs de navegação usando `<Link href="...">` do Next.js (não `onClick + location.href`). Rotas: "Quero aplicar" → `/mentoria#aplicar`, "Conhecer o método" → `/metodo`, "Conhecer a história" → `/sobre`.
- [ ] AC9: Layout responsivo validado em 375px (mobile), 768px (tablet) e 1280px (desktop). Sem overflow horizontal. Grid e split colapsam conforme protótipo.
- [ ] AC10: Metadata da HOME exportada: `title: 'Elevem-se — Mentoria para Casais'`, `description` alinhada ao brand book, `openGraph` com imagem `casal-01-web.jpg`.
- [ ] AC11: Lighthouse ≥ 90 nos 4 pilares (Performance, Accessibility, Best Practices, SEO) em desktop.
- [ ] AC12: Nenhuma violação do playbook ELEVEM-SE: sem versículo/amém, sem vocabulário de crise (superar/salvar/restaurar/reconciliar), promessa sempre de construção/elevação.

## Escopo

**IN:**
- `app/page.tsx` — página raiz SSG com metadata exportada.
- `components/home/Hero.tsx` — split editorial: H1 vinho, lead, 2 CTAs, foto `casal-01-web.jpg`, Card Quote flutuante.
- `components/home/Prova.tsx` — faixa cream com grid 2×2 de stats (+20 anos, 13 casamento, 3 filhos, 100% digital).
- `components/home/Dores.tsx` — split: SectionHead esquerda + lista numerada de 5 dores.
- `components/home/Conceito.tsx` — seção vinho, H2 centralizado, 3 sub-frases, frase itálica serifada.
- `components/home/MetodoResumo.tsx` — 2 cards ink/wine com as 2 fases, link "Ver o método completo".
- `components/home/Mentores.tsx` — split cream: foto `casal-02-web.jpg` + SectionHead + Signature + link "Conhecer a história".
- `components/home/Depoimentos.tsx` — grid 3 cards com depoimentos, Avatar, nome, papel.
- `components/home/Legado.tsx` — full-bleed `casal-bw-web.jpg` com overlay gradiente vinho + H2.
- `components/home/FinalCta.tsx` — Logo mark + eyebrow + H2 + lead + CTA primário.
- `components/layout/SiteNav.tsx`, `SiteFooter.tsx`, `MobileCTABar.tsx`.
- `components/shared/Reveal.tsx`, `SectionHead.tsx`, `Photo.tsx`, `Eyebrow.tsx`.
- Reimplementação TSX dos componentes do DS usados na HOME: `Button`, `Badge`, `Card`, `Quote`, `Signature`, `Avatar`, `Logo` — consumindo tokens via Tailwind v4 / CSS vars.

**OUT:**
- Implementação de páginas além de `/`.
- Formulário de aplicação real (ApplicationForm é stub/link no ciclo 1).
- Integração com CMS, analytics, newsletter real.
- Deploy em Vercel.
- Testes automatizados (E2E ou unitários — escopo de story de QA).

## Contexto Técnico

- **Fonte primária:** `site/docs/elevem-se-kv-site/project/site/home.html` (HTML do protótipo — verdade visual).
- **Referência de componentização:** `site/docs/elevem-se-kv-site/project/site/home.jsx` (estrutura de blocos).
- **Shared:** `site/docs/elevem-se-kv-site/project/site/shared/site-kit.jsx` (SiteNav, SiteFooter, MobileCTABar, Reveal, Eyebrow, Photo, SectionHead) e `shared/blocks.jsx` (LeadCapture usado no SiteFooter).
- **Tokens DS:** acessíveis via CSS vars (`--wine-600`, `--gold-500`, `--font-display`, `--space-*`) e mapeados em Tailwind v4 pelo sites-ux.
- **Screens de referência:** `site/docs/elevem-se-kv-site/project/screens/` — `01-home-scroll.jpg` a `04-home-scroll.jpg` para scroll completo; `01-home-sec.jpg` a `05-home-sec.jpg` para seções isoladas.
- **Fotos:** disponíveis em `public/photos/` após Story 1.1 concluída.
- **Animação Reveal:** usar Framer Motion (`motion.div` com `initial`, `whileInView`, `viewport`). Substituir o `IntersectionObserver` manual do protótipo.
- **Componentes client-side:** SiteNav (drawer state), SiteFooter (form state), MobileCTABar (scroll listener), Reveal (animação) → `"use client"`. Demais blocos → Server Components.
- **Bloqueada por Story 1.1** — projeto deve estar bootstrapado com tokens e assets disponíveis.
